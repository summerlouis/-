# Bao.Dumpling 三端同步版：使用与部署

更新：2026-10-28。本版保留现有菜单和界面，新增中央订单接口、桌号、WebSocket 即时通知、设备权限和模拟付款。原 Sites 云端站点没有切换；本版先用于本地测试，云端配置已准备但尚未部署。

## Windows 本地启动

1. 安装 Node.js 22.13.0 或更高版本，下载本分支完整源码并解压到固定文件夹。
2. 双击项目根目录的 **启动本地测试.cmd**。首次会安装依赖、初始化独立测试数据库。以后继续双击同一文件，不要更换数据文件夹。
3. 保持启动窗口打开。窗口会显示电脑地址及三种设备配对码。首次配对后保存 30 天，查看历史记录无需再次输入。顾客点餐无需配对。
4. 手机、iPad 和 Windows 连接同一个 Wi-Fi。Windows 防火墙询问时，允许此程序访问可信的专用网络；路由器不能阻止设备互访。

也可以在源码目录使用命令行：

```powershell
npm ci
npm run local:setup
npm run local:start
```

数据库迁移会记录已执行的版本，重复运行 setup 不会清空订单。初始菜单快照保留 A1 售价 €0.99、C6 南瓜粥已删除等当前设置；种子数据仅补充不存在的记录，不覆盖之后的后台改价。

启动窗口示例地址（以窗口实际显示的 IP 为准）：

| 设备 | 页面 |
| --- | --- |
| 手机：顾客点餐 | `http://192.168.0.193:5173/` |
| iPad：厨房接单 | `http://192.168.0.193:5173/kitchen` |
| Windows：收银 POS | `http://192.168.0.193:5173/pos` |
| 管理设备 | `http://192.168.0.193:5173/admin` |
| 历史记录 | `http://192.168.0.193:5173/owner` |

这是本次测试电脑的地址，换网络后可能改变。手机不能用 `127.0.0.1` 访问电脑，它指向手机自己。电脑关机、休眠或关闭启动窗口后，本地服务停止；这不代表数据被删除。

首次打开厨房页面，输入启动窗口中的“厨房设备配对码”；收银页面使用“收银设备配对码”；管理和历史页面使用“管理设备配对码”。不要把管理码发给顾客。需要更换设备身份时，点“退出设备配对”，再进入对应店员页面配对。

端口被占用时，先关闭之前启动的服务；或在 PowerShell 设置 `$env:BAO_PORT='5174'` 后运行 `npm run local:start`，所有设备相应改用 5174。

## 点餐与模拟付款

1. 手机选商品，堂食填写桌号，打包不需要桌号。可在网址后加 `?table=05` 预填 05 桌。
2. 确认提交后生成订单，收银台立即出现待付款单。
3. 顾客在小票上点“模拟付款”，或收银员点“确认模拟付款”，订单进入厨房。
4. 厨房依次操作“开始制作 → 待取餐 → 完成出餐”，手机订单及 POS 状态自动更新。

POS 自行开单时，填写桌号后点“模拟付款并发送厨房”。订单金额由服务器计算并保留成交价；重复提交同一个请求不会生成重复订单。已经提交的订单不随后台以后改价而变化。

页面顶部显示“模拟测试 · 不会扣款 · 不计入真实营业收入”。所有本版订单均标记为测试订单，实收金额为零，模拟金额单独记录。没有接入真实支付；不能把本测试版本用于真实收款记账。

“即时同步已连接”表示 WebSocket 已连通。断线时自动重连，另外保留备用轮询。断网不能成功提交新订单，购物车和待核对订单会保留；恢复网络后重试同一订单，避免重复下单。

## Cloudflare 云端部署（有账号后执行）

以下命令会创建并部署**新的模拟环境**，不自动迁移或切换原 Sites。使用你自己的账号；当前还没有账号，因此本轮未执行这些远程写入。

```powershell
npm ci
npm run cloud:configure
npx wrangler login
npx wrangler d1 create bao-dumpling-demo
npx wrangler r2 bucket create bao-dumpling-demo-images
```

打开生成的 `wrangler.bao.cloud.jsonc`，把 `database_id` 中的 `REPLACE_WITH_YOUR_D1_DATABASE_ID` 替换成创建数据库返回的真实 ID。若资源名称已被使用，需要同步修改配置中的 Worker、数据库、图片存储名称。`STORE_ID` 是该门店的固定标识，创建数据后不要随意修改。

配置已包含：

- `DB`：D1 中央订单和商品数据库。
- `BUCKET`：R2 商品图片。
- `ORDER_EVENTS`：Durable Object，负责门店 WebSocket 通知。
- `PAYMENT_MODE=mock`：服务器控制的模拟模式。
- `BAO_STANDALONE=true`：使用本应用的设备会话与门店权限。

数据库初始化与菜单导入：

```powershell
npx wrangler d1 migrations apply DB --remote --config wrangler.bao.cloud.jsonc
node scripts/menu-seed.mjs wrangler.bao.cloud.jsonc
npx wrangler d1 execute DB --remote --config wrangler.bao.cloud.jsonc --file .wrangler/catalog-seed.sql
```

分别生成四个随机值，建议每个 32 字节；在自己的终端运行下面命令，每运行一次得到一个新值：

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

再逐项写入云端秘密配置，按提示粘贴对应值，不写进仓库或聊天：

```powershell
npx wrangler secret put SESSION_SECRET --config wrangler.bao.cloud.jsonc
npx wrangler secret put ADMIN_DEVICE_CODE --config wrangler.bao.cloud.jsonc
npx wrangler secret put CASHIER_DEVICE_CODE --config wrangler.bao.cloud.jsonc
npx wrangler secret put KITCHEN_DEVICE_CODE --config wrangler.bao.cloud.jsonc
npx wrangler deploy --dry-run --config wrangler.bao.cloud.jsonc
npx wrangler deploy --config wrangler.bao.cloud.jsonc
```

保存 Worker 返回的 HTTPS 地址。手机打开该地址根路径，iPad 打开 `/kitchen`，Windows 打开 `/pos`。三端必须使用同一个域名；员工首次使用云端配对码配对。顾客无需 ChatGPT 账号。新域名只用于模拟环境，原 Sites 私有站点不会因此变成公开。

云端配置里的 `no_bundle` 配合 `scripts/build-bao.mjs` 生成独立 Worker；它复用现有商品、订单和图片 API，不依赖在云端运行 Windows。先完成跨设备验收，再决定是否迁移正式数据或更换当前入口。真实支付及正式营业模式不在本次交付范围。

**GitHub Pages 只能托管静态页面，不能单独运行这些数据库接口或 WebSocket。** 即使把页面放在 Pages，也仍需额外服务器或云服务。当前建议把前端和 API 一起部署到 Worker，避免跨域配置。
